# bitrixvm-php-hotfix

Срочное обновление PHP на виртуальной машине «1С-Битрикс» (BitrixVM 9), пока в репозиториях
ещё нет готового пакета.

21 октября 2026 года вышел PHP 8.2.35 — выпуск безопасности. Он закрывает две критические уязвимости,
[CVE-2026-109618](https://github.com/php/php-src/security/advisories/GHSA-w8hw-w9fx-j79w) и
[CVE-2026-109619](https://github.com/php/php-src/security/advisories/GHSA-6wmf-4rv5-p3rp)
(CVSS v4 9.2). Подробности — в [бюллетене php.net](https://www.php.net/archive/2026.php).
BitrixVM получает PHP из репозитория Remi. Пока зеркала Remi не синхронизированы, штатное обновление
через меню BitrixVM пакет 8.2.35 не находит. Скрипт собирает PHP 8.2.35 из исходников php.net с
параметрами пакетной сборки Remi и ставит его вместо 8.2.34.

> **Статус:** проверен на BitrixVM 9.0.10 (CentOS Stream 9, Apache с mod_php, PHP 8.2.34 из Remi).
> Сборка, сравнение с работающей версией, подмена и проверка через Apache прошли, портал работает.
> На других версиях BitrixVM скрипт не проверялся. Запускайте его только со снапшотом VM.

## На что рассчитан

- BitrixVM 9.0.10: CentOS Stream 9 (EL9), Apache с mod_php;
- PHP 8.2.34 из модульного репозитория Remi (`php:remi-8.2`).

Схема с запущенным php-fpm не поддерживается: скрипт это проверяет и останавливается.

## Что делает

1. Скачивает исходники PHP 8.2.35 с php.net и сверяет SHA-256 архива с опубликованной.
2. Ставит пакеты для сборки из BaseOS, AppStream, CRB и EPEL. Репозитории Remi при этом выключены:
   их метаданные на зеркалах сейчас рассинхронизированы.
3. Собирает PHP с параметрами пакета Remi. Параметры сняты с `php-devel-8.2.34` (`php-config`).
   Как и у Remi, сборок две. Первая — модуль Apache и модули расширений: собираются только те
   модули, что уже установлены на сервере. Вторая — консольный `php` и `php-cgi`. В неё
   вкомпилированы `pcntl` и `readline`, и в ней есть `chroot()`: в сборке вместе с модулем Apache
   PHP их не включает.
4. До подмены сравнивает новую сборку с работающей: модули, их функции, классы, значения ini,
   возможности gd. Разница в значениях ini по умолчанию закрепляется отдельным файлом в `/etc/php.d`.
   Любая другая разница останавливает скрипт, и он ничего не меняет.
5. Снимает копию прежних файлов и подменяет модуль Apache, `php`, `php-cgi` и встроенные модули
   расширений. Модули PECL не трогаются: номер API модулей в 8.2.35 тот же, 20220829.
6. Проверяет конфигурацию Apache и перезапускает его. Если Apache не поднялся, сам возвращает
   прежние файлы.
7. Проверяет версию в консоли и через Apache и сравнивает поведение с прежним.

На время сборки включается временная мера из бюллетеня php.net: `session.upload_progress.enabled = 0`.

## Запуск

Сначала сделайте снапшот VM. Скрипт копируйте на сервер в двоичном режиме: с виндовыми переводами
строк запуск упадёт с `bash\r: No such file or directory`. Тогда помогает
`sed -i 's/\r$//' php-8.2.35-hotfix.sh`.

```bash
bash php-8.2.35-hotfix.sh build      # сборка, проверка, подмена, перезапуск Apache, проверка
bash php-8.2.35-hotfix.sh verify     # только проверка
bash php-8.2.35-hotfix.sh rollback   # вернуть файлы 8.2.34 из копии
```

Ключи:

- `--yes` — не спрашивать про снапшот;
- `--reconfigure` — сконфигурировать и собрать заново;
- `--force` — подменить, несмотря на разницу в функциях и классах.

Повторный запуск безопасен: сделанные шаги пропускаются, прерванная сборка продолжается.
Рабочий каталог — `/root/php-build`, его можно сменить переменной `WORK`. Журнал лежит в
`/root/php-build/state/hotfix.log`. Для проверки через Apache скрипт перебирает все порты httpd
и запоминает тот, на котором отвечает сайт. Адрес можно задать и явно, переменной `APACHE_URL`,
например `APACHE_URL=http://127.0.0.1:8888`. Корень сайта задаётся переменной `DOCROOT`
(по умолчанию `/home/bitrix/www`).

Вывод цветной. В журнал цвет не пишется; отключить его можно переменной `NO_COLOR=1`.

## Как убедиться, что версия сменилась

Меню BitrixVM («Update PHP, MySQL, PostgreSQL») может не сразу показать 8.2.35: скрипт заменяет
файлы PHP, а пакеты в системе остаются прежними. Фактическую версию показывают:

- `php -v` — консоль;
- `bash php-8.2.35-hotfix.sh verify` — консоль и Apache;
- административный раздел Битрикс — версия, которой работает сайт.

## После выхода пакета

Когда в репозиториях Remi появится PHP 8.2.35, обычное обновление через меню BitrixVM заменит собранные
файлы пакетными. После этого `/etc/php.d/zz-cve-2026-109619.ini` можно удалить. Поддержка ветки 8.2
заканчивается 31 декабря 2026 года, переход на 8.3 или 8.4 стоит планировать.
